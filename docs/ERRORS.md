# 오류 보여주기

작성: 2026-10-29 · 근거: 오류 화면 전수 조사(28개 장면, 16개 문제)

오류는 **무엇이 잘못됐는지, 어디서, 다음에 무엇을 하면 되는지**를 한눈에 알려야 한다. 드라이버 원문은 숨기지 않되 앞에 내세우지 않는다.

## 1. 원칙

1. **하나의 컴포넌트.** 모든 오류는 `ErrorNotice`(박스)나 `FieldError`(칸 아래 한 줄), 오류 토스트 중 하나로 보인다. 손으로 만든 오류 마크업과 따로 노는 빨간 글자 클래스는 없앤다.
2. **설명 먼저, 원문은 접어서.** 보이는 줄은 사람 말로 쓴 제목과 한 줄 원인이다. 드라이버 원문, 오류 코드(SQLSTATE, `mongo_11000`), 위치는 "자세히"에 넣고 복사할 수 있게 한다. 규칙에 맞지 않는 오류도 원문의 첫 줄만 제목으로 쓰고 나머지는 접는다(Rust `Debug` 덤프가 화면에 펼쳐지는 일이 없다).
3. **원인에 붙인다.** 칸 값 오류는 그 칸 아래, 셀 편집 실패는 그 셀, 필터 오류는 그 필터 줄, SQL·mongosh·집계 구문 오류는 편집기의 그 위치(밑줄 + 줄·열), 가져오기 실패는 그 줄을 표시한다.
4. **다음 할 일을 준다.** 고칠 방법은 지금 있는 화면에 맞는 것만 보여주고(연결 창 안에서 "연결을 편집하세요"라고 하지 않는다), 할 수 있으면 버튼으로 준다(다시 시도, 직접 연결 켜기, SSL 끄기, 스키마 새로고침, 검증 탭 열기).
5. **사라지지 않는다.** 실패는 2.4초 뒤 사라지는 알림으로 보내지 않는다. 오류 토스트는 빨간색이고 닫을 때까지 남으며 복사할 수 있다. 성공 알림만 잠깐 보였다 사라진다.
6. **제자리에서 수명이 끝난다.** 오류는 생긴 탭·패널에 속한다. 그 작업을 버리거나 다시 불러오거나 성공하면 지워지고, 다른 탭으로 따라가지 않는다.
7. **화면을 밀지 않는다.** 데이터 탭과 결과 위 오류는 레이아웃을 밀어내지 않는 자리(그리드 위 겹침 띠)에 나오고, 실패한 다시 불러오기 뒤의 옛 행은 흐리게 보여 "옛 결과"임을 알린다.
8. **한 번만.** 같은 오류를 여러 곳(사이드바와 콘솔, 알림과 상태 줄, 단계 카드 세 곳)에 겹쳐 보이지 않는다.
9. **연결이 끊기면 앱 전체 상태로.** TablePeek 서버가 응답하지 않으면 앱 위쪽 띠 하나로 알리고 자동으로 다시 붙어 보며 "다시 연결" 버튼을 둔다. 서버가 다시 시작되어 토큰이 바뀌었으면 그렇게 말하고 새 주소로 여는 방법을 준다. 이때 패널마다 같은 오류를 띄우지 않는다.
10. **위험한 확인은 앱 대화상자로.** `window.confirm`을 쓰지 않는다. 지우기는 위험 색을 쓰고, 데이터베이스 삭제는 이름 입력을 받는다(안전 모드 규칙을 따른다).
11. **접근성.** 오류는 `role="alert"`(토스트·박스) 또는 `aria-live="polite"`(칸 아래 줄), 잘못된 입력은 `aria-invalid`와 `aria-describedby`로 오류 줄을 가리킨다.

## 2. 서버가 주는 오류

REST와 WebSocket 오류는 지금처럼 `{ code, message }`이고, 알 수 있으면 다음을 덧붙인다(모두 선택).

```jsonc
{
  "code": "postgres_error",
  "message": "relation \"orderz\" does not exist",   // 사람에게 보일 첫 줄. 접두어 "내부 오류:" 같은 포장 없음
  "sqlstate": "42P01",                                // SQL 엔진
  "position": { "offset": 15 },                       // 문장 안 1부터 센 글자 위치 (PG), 또는 { "line": 3, "column": 7 }
  "server_code": 11000,                               // 엔진 고유 번호 (MongoDB, MySQL errno, MSSQL number)
  "code_name": "DuplicateKey",                        // MongoDB codeName
  "details": { … },                                   // MongoDB errInfo(검증 실패 이유 등), canonical EJSON
  "raw": "…"                                          // 드라이버 원문 전체 (자세히에만 보임)
}
```

- 사용자가 고칠 수 있는 실패(인증, 연결 거부, 타임아웃, 문법, 제약 위반)에 "내부 오류"를 붙이지 않는다. "TLS 연결 실패"는 원인이 TLS일 때만 붙인다.
- 토큰이 맞지 않으면 401 `{ code: "invalid_token" }`. 웹은 이것으로 "서버가 다시 시작됨"을 알아낸다.

## 3. 웹 구성

- `ErrorNotice`: `block`(패널·대화상자), `compact`(좁은 자리), `banner`(그리드·결과 위 겹침 띠). 제목 · 원인 한 줄 · 고칠 방법(맥락에 맞는 것만) · 동작 버튼(다시 시도, 규칙의 원클릭 수정, 호출 쪽 동작) · "자세히"(코드·위치·원문, 복사).
- 되돌리기 보고(`AppError.undo = { undone: string[], left: [{ change, reason }] }`): 트랜잭션이 없는 엔진에서 적용이 중간에 실패해 웹이 앞의 변경을 되돌리면(docs/ENGINES.md §4.1), `ErrorNotice`가 모든 모양(`banner` 포함)에서 제목 바로 아래에 짧은 목록으로 보인다. 한 줄 요약("앞서 적용한 변경 N개를 되돌렸습니다" 또는 "…N개는 남았습니다. 새로고침해 확인하세요"), 되돌리지 못한 변경(오류 색, 이유와 함께)이 먼저, 되돌린 변경이 그 뒤. 길면 목록만 스크롤되고, 복사하면 함께 들어간다. "자세히"에 접지 않는다.
- `FieldError`: 칸 아래 한 줄. 입력에 `aria-invalid`, `aria-describedby`.
- 오류 토스트: `notify`와 따로 `notifyError(error, { retry? })`. 빨간색, 닫을 때까지, 복사.
- `explainError(error, context)`: `context`는 `"connect" | "editor" | "data" | "import" | "export" | "structure" | "document" | "shell" | "aggregation" | …`. 규칙의 고칠 방법은 맞는 맥락에서만 나온다. 엔진별 규칙은 `engines/<id>/`에 둔다.
- 앱 연결 띠: 소켓·REST가 서버에 닿지 못하면 한 곳에서 상태를 관리하고, 그동안 패널의 같은 오류는 띄우지 않는다.
- `ConfirmDialog`: `window.confirm` 대신. 위험 동작은 빨간 버튼, 필요하면 이름 입력.
